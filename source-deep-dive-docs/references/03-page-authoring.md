# 阶段③ 撰写：单页怎么写

一次只写一页，写完立刻核验一页。不要「全部写完再一起检查」——错误会被复制到后面每一页。

---

## 0. 动笔前

1. 打开阶段①的**事实清单**，把属于这一页的条目筛出来
2. 打开对应**源码**（编辑器里定位到行，方便逐字复制）
3. 复制 `templates/page.html` 做骨架
4. 确认**上一页和下一页**是哪两页（侧栏与翻页要同步）

**一条纪律**：写每一段时问自己「这句的依据是清单里的哪一条」。答不出来，就回源码补读或者删掉这段。

---

## 1. 一节（`<h2>`）的标准写法

每节按这五步展开，读者会很快习惯这个节奏：

```html
<h2>3. 权限判定的四步收敛</h2>

<p><strong>结论先行</strong>：判定顺序是「显式拒绝 → 显式允许 → 策略默认 → 插件故障取拒绝」，
前两步任一命中就返回，后面的不再执行。</p>

<div class="src-block">path/to/PermissionManager.java:180-206</div>

<pre><code class="language-java">…15~30 行，从源码逐字复制…</code></pre>

<div class="table-scroll">
  <table>
    <thead><tr><th>步</th><th>做什么</th><th>要点</th></tr></thead>
    <tbody>
      <tr><td>①</td><td>查显式拒绝</td><td>拒绝的优先级最高，命中即返回</td></tr>
    </tbody>
  </table>
</div>

<div class="callout design">
  <span class="callout-title">为什么故障时取「拒绝」而不是「允许」</span>
  <p>…为什么这样而不是那样…</p>
</div>
```

**五个构件的分工**：结论（读者可以先只看这行）→ 出处（想自己看的入口）→ 代码（证据）→ 表格（把代码里的步骤对上）→ 依据（设计意图）。

## 2. 引用规范

### 格式

```
相对路径/文件.扩展名:行号           单行
相对路径/文件.扩展名:起-止          区间
相对路径/文件.扩展名:起, 另处-另处    多处（同一文件）
```

### 三条硬规则

**① 路径必须写到能唯一确定。** 大型项目里同名文件极多（`Config.java`、`pom.xml`、`index.ts` 满地都是）。**带文件名而不带路径的引用，在核验脚本里会报「歧义」**，且读者也无法定位。

- 够用就好：从模块/包名开始即可，`src/main/java/com/x/core/PermissionManager.java:180`
- 跨仓库 / 多语言工作区：带上仓库名，`<repo>/jellyfish-api/src/main/java/…/PromptPlacement.java:26`

**② 行号必须来自你刚才打开的那个版本。** 中途改过源码、或隔了几天回来接着写，一定要重新确认行号——**行号漂移是这套文档最脆的资产**。

**③ 引用区间时选「不易动」的位置。** 优先引：方法签名、类声明、常量定义、一段完整的 try/catch、一个完整的循环。避免引：单个 `}`、一行只有括号、文件末尾几行（改动时会整体漂移）。

### 引用注释是允许且常见的

引 javadoc / 块注释原文（讲解设计意图的段落）**不算错误**，但要意识到：「首行是注释」会让自动化核验把它归入「需人工确认」的一类。引注释时**写明这是注释**，例如：

```
<div class="src-block">path/AskChannel.java:44-49（类注释，解释为什么永不超时）</div>
```

## 3. HTML 转义 —— 最容易出错的地方

代码片段里的 `<` 与 `&` **必须转义**，否则浏览器会把它们当标签，页面结构直接崩坏。

| 源码里的字符 | HTML 里写成 |
|---|---|
| `<` | `&lt;` |
| `>` | `&gt;`（可省，但建议统一写） |
| `&` | `&amp;` |

**高危场景**（几乎必踩）：

- Java/C++ 泛型：`List<LlmMessage>` → `List&lt;LlmMessage&gt;`
- 比较运算符：`if (a <= b)` → `if (a &lt;= b)`
- Lambda 箭头（安全）：`->` 不用转义，但 `<` 开头的 lambda 参数注解要转
- 位运算与移位：`x >> 2` → `x &gt;&gt; 2`
- 正则与字符串里的 `&`、`<`：`"a<b"` → `"a&lt;b"`
- XML/HTML 配置片段：整个片段里所有 `<` 都要转
- TypeScript 泛型、Rust 生命周期与泛型、Go 的 channel 操作符（`<-` 要转）

**检查方法**：写完后全文搜 `&lt;` 与 `&gt;` 的数量是否与源码里对应字符数量匹配；或者直接打开页面看结构有没有炸。**核验脚本查不出转义问题**，只能靠这一步。

**另一个反向坑**：`&lt;` 写进**正文解释性文字**里是错的（正文本来就该用真正的 `<`）。只有代码块与行内 `<code>` 里才需要转义。

## 4. 代码块

```html
<pre><code class="language-java">…</code></pre>
```

**规则**：

- `class="language-xxx"` 里的 xxx 必须与高亮库的语言标识一致（`java` / `python` / `bash` / `json` / `xml` / `javascript` / `typescript` / `go` / `rust` / `sql` / `yaml` / `diff` / `text`）。**写错不会报错，只会不高亮。**
- 纯文本 / 目录树 / 输出示例用 `language-text`（或留空）
- **逐字复制**，包括缩进、空行、注释。不要「顺便整理格式」——整理过就不再是证据，且和行号意味的内容可能不符
- 长度 **15~30 行**。少于 10 行通常说明这段没啥可讲的；多于 40 行读者会跳过
- 需要省略时在代码里用注释标明，**不要静默删行**：`// …（此处省略 30 行参数校验）…`
- 代码里不要再重复写文件路径（已有 `src-block` 出处行）
- 加 `data-anchor="stable-name"` 可以固定这一块的锚点 ID（不写则按出现顺序自动编号）：

```html
<pre data-anchor="perm-decide"><code class="language-java">…</code></pre>
```

## 5. 表格

**用表格的场景**：步骤分解、字段/参数清单、多方案对比、状态与条件映射、术语对照。**判据：内容有「列」的结构。**

```html
<div class="table-scroll">
  <table>
    <thead><tr><th>列1</th><th>列2</th></tr></thead>
    <tbody><tr><td>…</td><td>…</td></tr></tbody>
  </table>
</div>
```

- **必须用 `.table-scroll` 包裹**：窄屏上表格会撑破布局
- 表格里可以放 `<code>` 做行内代码（**正文里的行内代码用真正的尖括号，不要转义**）
- 单元格里要强调用 `<strong>`，不要用大段说明——表格是速查，不是散文
- 列数控制在 4 列以内，第 3、4 列会开始难读

## 6. 图：先想清「这张图回答什么」

**每张图都必须配一行 `figure-cap` 说明它在回答什么问题。** 没有说明的图读者只会跳过。

```html
<div class="mermaid">
flowchart TD
  A["入口"] --> B["装配"]
  B --> C{"有插件?"}
  C -->|是| D["加载"]
  C -->|否| E["空实现"]
</div>
<p class="figure-cap">图 03-1　启动装配的两条路径：装与不装插件的差别在哪一步分叉</p>
```

### 选型表

| 要表达什么 | 用什么 |
|---|---|
| 流程、分支、依赖关系、分层 | `flowchart TD`（自上而下）/ `flowchart LR`（左右） |
| 多个组件按时间交互（请求-响应、调用序列） | `sequenceDiagram` |
| 状态与转移条件 | `stateDiagram-v2` |
| 数据表结构与关系 | `erDiagram` |
| 占比、趋势 | 不要用 mermaid，用表格反而更清楚 |

### mermaid 语法坑（会静默渲染失败）

- **标签含特殊字符必须加引号**：`(`、`)`、`/`、`<`、`>`、`#`、`:`、中文标点、空格混合时，写成 `A["含 (括号) 的标签"]`。不加引号经常渲染成空白或报错。
- **换行用 `<br/>`**（依赖渲染库的 `htmlLabels: true`，`templates/app.js` 已配好）
- **节点 ID 不要用保留字**：`end`、`graph`、`subgraph`、`class`、`state`、`default`。用 `endNode` 之类替代
- **注释**用 `%%`
- **边上的标签**用 `-->|文字|` 或 `-. "文字" .->`（虚线跨长距离时更清楚）
- **子图（subgraph）里不要嵌套太深**，超过两层布局会很难看
- **样式**尽量别自定义（`style` / `classDef`），深色模式适配会崩
- 渲染失败要有兜底：`templates/app.js` 会把失败的图**原样显示源码**，至少内容不丢

## 7. 旁注块（callout）

四种类型，各有明确用途，**不要混用**：

| 类型 | 用于 | 不该用于 |
|---|---|---|
| `callout design` | **设计依据**：为什么这样而不是那样 | 复述代码在做什么 |
| `callout pitfall` | **坑点**：哪里容易踩、现象是什么、怎么避开 | 抱怨代码写得烂 |
| `callout warn` | **危险**：会造成数据损坏 / 安全问题 / 不可逆后果 | 一般性的注意 |
| `callout tip` | **经验**：省时间的技巧、阅读方法 | 重复正文已有的内容 |

```html
<div class="callout pitfall">
  <span class="callout-title">坑点：故障是静默的</span>
  <p>…现象 + 原因 + 怎么发现…</p>
</div>
```

**`callout design` 是这套文档的核心构件**，每页至少一个。写法：

1. 先说清「代码选了 A」
2. 再给出「显而易见的替代方案 B」
3. 然后说明**为什么 A 更好**——依据要来自源码里的证据（注释、约束文档、失败路径的处理代码）

**好例子的形态**：「这里不用重试，因为失败的原因是配置错误，重试只会让故障延迟暴露。」——它给出了一个可判断的理由，而不是「为了健壮性」。

## 8. 措辞规范

**必须**：

- **先结论后依据**。每节第一句话就是这一节的答案，别铺垫
- **说清「不是另一种做法」**。比较句比陈述句有信息量：「这里用轮询而不是回调，因为……」
- **给数字时带出处**。写「上限 500 条」就附 `:135`
- **术语首次出现给中英对照**：「边界（boundary）」
- **不确定就明说**：「未在源码中找到相关校验」「该行为未在测试中覆盖」
- **同一概念全文用同一个词**。不要这段叫「装配」那段叫「组装」

**禁止**：

- 「显然」「众所周知」「很简单」「只要……就行」——读者卡住时这些词最伤人
- 用行业黑话替代解释；如果必须用，第一次出现时给定义
- 大段复述代码在做什么（读者能看代码）。正文要讲**代码看不出来的**：意图、约束、历史、权衡
- 把「待确认」写成肯定句（**这是最严重的问题**——虚假的确定性比明确的空白有害得多）
- 凭函数名 / 类名推测行为。名字会骗人（`isValid()` 可能从不返回 false）

---

## 9. 篇幅与节奏

- 单页 **300~800 行 HTML**。超了就在 `callout` 处找自然的拆分点，拆成两页并调整编号
- 每 2~3 屏要有一个表格或图，防止长段落堆积
- `h2` 之间不要超过 3 个 `h3`
- 关键结论写 **4~6 条**，每条 1~2 句话，**能独立阅读**（只读结论的人也要拿到要点）
- 页脚写清「本页依据」——列材料，不写「综合整理」这种空话

## 10. 常见写作错误（写完自己对照一遍）

| 症状 | 问题 | 改法 |
|---|---|---|
| 大段代码 + 一句「如上所示」 | 没有解读 | 加表格逐步对上 |
| 全是「是什么」，没有「为什么」 | 变成了目录转写 | 补 `callout design` |
| 每节都从「首先我们来看」开始 | 读者要先读三行才知道讲什么 | 结论先行 |
| 引用只有行号没有文件名 | 读者无法定位 | 补全路径 |
| 代码块里 `List<String>` 没转义 | 页面结构崩坏 | 全文转义检查 |
| 图没有 `figure-cap` | 读者不知道图在说什么 | 每图一行说明 |
| 结论里出现正文没讲过的东西 | 结论成了新知识 | 挪回正文 |
| 学习目标写「了解 XX」 | 无法自测 | 改写成可验证的：「能说出 XX 的三个触发条件」 |
| 引用了「其他版本」的行号 | 行号漂移 | 回源码重新确认 |
